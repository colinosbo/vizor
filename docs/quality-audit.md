## Cleanup and data boundaries

The cleanup inventory and local results are under ignored `artifacts/quality-audit`. Signing material, native project evidence, the active build bundle, real workspaces, account configuration and conversation databases were preserved. Recycled folders still occupy disk space until the Recycle Bin is emptied; they were not reported as reclaimed free space. No Vizor installers were found in Downloads during the inventory.

Before installation, the real workspace database was backed up under its own `data/backups` directory. Readback preserved 6 agents, 6 conversations, 94 messages, 60 runs, 47 proposals and 38 terminal dispatches. The user requested subscription-only use, so the saved Anthropic connection was removed. Existing chats and worker records were preserved after upgrade. Subscription mode is selected without enabling automatic task approval or delivering existing assignments.

## Subscription use

Choose **Orchestrator settings → Claude Code subscription → Set up Claude subscription**, complete Claude Code's own sign-in and choose the Claude subscription account. Workers use the same dedicated native profile. Sign-in tokens and passwords are not copied into Vizor's database. Native subscription responses are excluded from API dollar totals; API spending caps do not measure subscription allowance. Authentication failures and usage limits do not trigger a paid API fallback.

The implementation follows Claude Code's [native authentication](https://code.claude.com/docs/en/iam) and [CLI interface](https://code.claude.com/docs/en/cli-reference). Fixture tests do not prove that a particular subscription has available usage or that every possible project workflow is bug-free.
